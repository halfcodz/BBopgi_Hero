# 뽑기키우기 (BBopgi Hero) 게임 기획서

> 버전 0.1 · 2026-10-04 · 엔진 Godot 4.7 (GDScript) · 세로형 모바일(720×1280) 우선, PC 동시 지원

---

## 1. 한 줄 요약

**인형뽑기 기계로 귀여운 새끼 드래곤을 뽑고, 그 드래곤들이 알아서 스테이지를 돌며 모아 온 코인으로 다시 뽑기를 하는 방치형 수집 RPG.**

## 2. 기획 의도와 시장 포지션

### 2.1 요즘 방치형 시장에서 먹히는 것

| 흐름 | 대표 사례 | 우리 게임에 가져올 것 |
|---|---|---|
| 뽑기가 곧 성장인 방치형 | 버섯커 키우기, 운빨존많겜 류 | 뽑기 = 성장의 주 동력. 초반에 뽑기를 아끼지 않고 "많이" 준다 |
| 짧고 강한 첫 세션 | 대부분의 하이퍼캐주얼 → 방치형 전환작 | 첫 5분 안에 10연차 + 영웅 확정, 첫 1시간 안에 첫 환생 |
| 숫자가 커지는 쾌감 | 탭 타이탄 계열 | 큰 데미지 숫자, 골드 분수, K→M→B→T 단위 상승 |
| 물리적 손맛 있는 가챠 | 현실 인형뽑기, 캡슐토이 | 집게를 직접 움직이고 떨어뜨리는 조작 + 흔들림 연출 |
| 등급 승급 연출 | 서브컬처 가챠 전반 | 캡슐 빛 색이 파랑→보라→금→무지개로 "올라가는" 리빌 |

### 2.2 차별점

1. **조작하는 가챠** — 버튼 한 번이 아니라 집게를 움직여 떨어뜨린다. 결과 확률은 고정(공정성), 조작 실력은 "퍼펙트 보너스"로만 보상한다.
2. **키우는 맛이 보이는 드래곤** — 별(★)이 오를 때마다 외형이 바뀐다(뿔 → 날개 → 왕관 → 오라).
3. **한 화면 두 루프** — 화면 위쪽에선 항상 전투가 돌아가고, 아래쪽에서 뽑기·성장을 한다. 뽑는 동안에도 골드가 쌓이는 게 눈에 보인다.

### 2.3 타깃

- 출퇴근·자기 전 3~10분 짧게 들어오는 모바일 유저
- 귀여운 캐릭터 수집을 좋아하는 10~30대
- 과금 압박 없이 "많이 뽑는 맛"을 원하는 라이트 유저

## 5. 인형뽑기(가챠) 시스템

### 5.1 조작과 흐름

1. **1회 뽑기 (1코인)**
   - 좌우 버튼(또는 드래그)으로 집게를 움직인다. 제한시간 10초가 지나면 자동으로 떨어진다.
   - **[내리기]** → 집게가 내려가 가장 가까운 캡슐을 집는다.
   - 올라오는 동안 캡슐이 **흔들린다**(긴장감). 결과는 이미 정해져 있으므로 실패는 없다. 반드시 배출구까지 옮긴다.
   - 배출구에서 캡슐이 열리며 **등급 리빌 연출** → 드래곤 등장.
2. **10회 뽑기 (10코인)**
   - 집게가 기계 안을 휩쓸며 캡슐 10개를 한꺼번에 쓸어 담는 "와르르" 연출.
   - 카드 10장이 뒤집히는데, **가장 높은 등급은 마지막에** 공개한다.
   - **10회 뽑기마다 영웅(SR) 이상 1개 확정**.
3. **퍼펙트 보너스** (1회 뽑기 전용)
   - 집게가 캡슐 정중앙 ±8px 안에 떨어지면 "PERFECT!" → 뽑은 드래곤의 별조각 +1.
   - **등급 확률에는 영향을 주지 않는다.** 실력은 덤으로만 보상해서 공정성을 지킨다.

### 5.2 등급과 확률 (뽑기 기계 Lv.1 기준)

| 등급 | 이름 | 색 | 확률 | 기본 공격력 | 드래곤 수 |
|---|---|---|---|---|---|
| N | 일반 | 회색 | 60.0% | 10 | 5 |
| R | 희귀 | 파랑 | 28.0% | 14 | 5 |
| SR | 영웅 | 보라 | 9.0% | 21 | 4 |
| SSR | 전설 | 금색 | 2.7% | 32 | 4 |
| UR | 신화 | 무지개 | 0.3% | 50 | 2 |

### 5.3 천장(보호 장치)

| 장치 | 내용 |
|---|---|
| 영웅 확정 | SR 이상이 9회 연속 안 나오면 10번째는 SR 이상 |
| 전설 소프트 천장 | 60회째부터 SSR 이상 확률이 회당 +2.5%p 증가 |
| 전설 하드 천장 | 90회째는 SSR 이상 확정 |
| 신화 마일리지 | 뽑기 300회분 마일리지로 신화 드래곤 1종 선택 교환 |
| 첫 10연 | 계정 첫 10회 뽑기는 영웅 이상 1개 확정 (일반 규칙과 같지만 튜토리얼에서 강조) |

### 5.4 뽑기 기계 레벨 (누적 뽑기 횟수로 성장)

뽑을수록 기계가 성장해서 상위 등급 확률이 오른다. "많이 뽑을수록 좋아진다"는 감각을 주고 다음 목표를 계속 보여 준다.

| 1 | 0 | 60.0 | 28.0 | 9.0 | 2.7 | 0.3 |
| 2 | 30 | 57.0 | 29.5 | 10.0 | 3.1 | 0.4 |
| 3 | 100 | 54.0 | 31.0 | 11.0 | 3.5 | 0.5 |
| 4 | 250 | 50.0 | 33.0 | 12.2 | 4.1 | 0.7 |
| 5 | 500 | 46.0 | 35.0 | 13.5 | 4.6 | 0.9 |
| 6 | 1000 | 42.0 | 36.5 | 15.0 | 5.3 | 1.2 |
| 7 | 2000 | 38.0 | 38.0 | 16.5 | 6.0 | 1.5 |

### 5.5 리빌 연출 단계 (도파민 핵심)

| 단계 | 연출 | 등급 |
|---|---|---|
| 1 | 캡슐이 흰빛으로 흔들림 | 전부 |
| 2 | 빛이 파랑으로 바뀜 + "띵" | R 이상 |
| 3 | 보라로 **승급** + 화면 살짝 흔들림 | SR 이상 |
| 4 | 금색으로 **승급** + 파티클 폭발 + 슬로모션 | SSR 이상 |
| 5 | 무지개 + 화면 플래시 + 전용 팡파레 | UR |

- 승급은 한 단계씩 순서대로 보여 준다. "어? 또 올라가?" 하는 순간이 핵심 쾌감이다.
- NEW 뱃지, 중복이면 "★조각 +1" 토스트를 띄운다.
- 10연 결과 화면에서 최고 등급 카드는 0.5초 늦게 뒤집는다.

### 5.6 공정성·법적 고려

- 확률형 아이템 확률 공시가 법적 의무다(게임산업진흥법, 2024년 3월 시행). 뽑기 화면에 **[확률 보기]** 버튼을 넣고 기계 레벨별 확률과 천장 규칙을 모두 공개한다.
- 결과는 **[내리기] 시점에 확률표로 결정**된다. 집게 위치는 연출일 뿐 확률에 개입하지 않는다.
- 뽑기 코인을 유료로 팔 경우에도 같은 확률을 적용하고 공시한다.

### 6.5 편성

- 파티 슬롯은 최대 5칸이다. 1-1에서 1칸, 1-3에서 2칸, 1-6에서 3칸, 2-1에서 4칸, 3-1에서 5칸이 열린다.
- **[자동 편성]** 버튼으로 전투력 상위 드래곤을 배치한다. 초반 편의를 위해 새 드래곤이 더 강하면 자동으로 교체할지 묻는다.

## 7. 스테이지와 전투

### 7.1 구조

- **챕터 × 10 스테이지**. 스테이지 표기는 `챕터-번호` (예: 3-7).
- 각 스테이지는 **일반 웨이브 4개(웨이브당 적 3마리) + 보스 1마리**로 이뤄진다.
- x-1 ~ x-9의 보스는 **스테이지 보스**(체력 6배, 제한시간 20초), x-10의 보스는 **챕터 보스**(체력 25배, 제한시간 30초)다.
- 보스를 제한시간 안에 못 잡으면 같은 스테이지를 **자동 반복**한다. 반복하는 동안에도 골드는 계속 쌓이므로 레벨업 후 다시 도전하면 된다(방치형의 자연스러운 벽).

### 7.2 수치 공식 (s = 0부터 시작하는 누적 스테이지 번호, 1-1 = 0)

| 항목 | 공식 |
|---|---|
| 일반 적 체력 | `40 × 1.21^s` |
| 적 공격력 | `1.5 × 1.20^s`, 맨 앞 적만 공격 (보스 3배). 파티 체력을 깎고, 파티가 쓰러지면 스테이지 재시작 |
| 파티 체력 | 드래곤별 `기본체력 × 레벨배율 × 별배율`의 합 (기본체력 N 60 / R 80 / SR 110 / SSR 150 / UR 220), 웨이브 사이에 30% 회복 |
| 처치 골드 | `5 × 1.19^s` (보스는 8배) |
| 웨이브 간격 | 적 등장까지 약 3초 |

### 7.3 챕터 테마

| 챕터 | 이름 | 배경색 | 등장 적 | 기믹(추후) |
|---|---|---|---|---|
| 1 | 말랑 버섯숲 | 연두 | 슬라임, 버섯돌이 | 튜토리얼 |
| 2 | 사탕 해변 | 민트 | 젤리게, 솜사탕 | 물 속성 적 다수 → 상성 소개 |
| 3 | 구름 산맥 | 하늘 | 구름양, 번개새 | 5번째 슬롯 오픈 |
| 4 | 용암 동굴 | 주황 | 마그마볼, 박쥐 | **첫 벽 → 둥지 이사 해금** |
| 5 | 얼음 성 | 하늘빛 | 눈덩이, 얼음기사 | 적 공격 둔화 |
| 6 | 별하늘 신전 | 남색 | 별요정, 수호상 | 빛·어둠 적 |
| 7 이후 | 테마 순환 + "어려움 n단계" 표기 | | | 무한 진행 |

### 7.4 탭·피버

- 전투 화면을 탭하면 **파티 공격력 합의 5%**로 추가 타격한다(데미지 숫자 표시).
- 탭 1회마다 피버 게이지가 4% 찬다. 가득 차면 **피버 10초**: 공격 속도 2배, 골드 2배, 화면 테두리가 빛난다.

### 7.5 오프라인 보상

- 마지막 접속부터 최대 **8시간**까지 누적한다.
- 골드 = 최근 1분간 측정한 초당 골드 × 경과 초 × 60%
- 코인 = 경과 10분당 1
- 접속하면 "자는 동안 드래곤들이 모아 왔어요!" 팝업을 띄운다(금화가 쏟아지는 연출).

## 8. 레벨 디자인 (페이싱)

### 8.1 목표 곡선

밸런스 시뮬레이터(`tools/balance_sim.py`)로 위 공식을 그대로 돌려 본 결과다. 매 순간 골드를 전부 레벨업에 쓰고 코인을 전부 뽑기에 쓰는 플레이어를 가정했다.

| 시점 (활동 시간) | 도달 | 이때 플레이어가 느끼는 것 |
|---|---|---|
| 0~1분 | 1-1 ~ 1-3 | 시작 10코인 → 10연 뽑기, 영웅 확정, "와 귀엽다" |
| ~5분 | 2-1 | 슬롯 4칸, 첫 챕터 보스 처치 +20코인 → 두 번째 10연 |
| ~11분 | 3-1 | 슬롯 5칸 완성, 상성 체감 |
| ~22분 | 4-1 | 진행이 눈에 띄게 느려짐(첫 벽) |
| ~45분 | 4-x 정체 | **둥지 이사 해금 → 첫 환생** (비늘 약 5개, +25%) |
| ~1.5시간 | 5-x | 두 번째 환생, 처음보다 훨씬 빠르게 4챕터 돌파 |
| ~3시간 | 7-1 | 전설 드래곤 2~3마리, 별 3~4 |
| 1일차 끝 | 10~13챕터 | 기계 Lv5 근처, 신화 1마리 가능성 |

### 8.2 페이싱 원칙

1. **첫 5분은 무조건 빠르게**: 스테이지당 20~40초, 막힘이 없다.
2. **벽은 보스에만 둔다**: 일반 웨이브는 항상 진행되고, 막히는 곳은 보스다. 벽을 넘는 수단(레벨업 / 뽑기 / 편성 / 환생)을 항상 2개 이상 열어 둔다.
3. **비용 곡선 1.10 > 효과 곡선 1.07**: 레벨업만으로는 점점 느려지고, 뽑기(별 배율)와 환생(비늘 배율)이 그 차이를 메운다. 세 시스템이 모두 의미를 갖게 된다.
4. **보상 간격 30초 규칙**: 30초마다 무언가 하나는 일어나게 한다(웨이브 클리어, 레벨업 가능 표시, 코인 획득, 피버).
5. **다음 목표 상시 노출**: 상단에 "다음 슬롯까지 2스테이지", "기계 Lv3까지 12회"처럼 다음 목표를 항상 띄운다.

### 8.3 둥지 이사 (환생)

| 항목 | 값 |
|---|---|
| 해금 | 최고 스테이지 4-1(s=30) 도달 |
| 획득 비늘 | `floor(((최고 s - 20) / 10)^1.5 × 2)` |
| 효과 | 비늘 1개당 공격력 +5%, 골드 +5% (영구, 합연산) |
| 초기화 | 스테이지 → 1-1, 골드 → 0, 드래곤 레벨 → 1 |
| 유지 | 드래곤, 별, 코인, 마일리지, 기계 레벨, 도감 |
| 권장 타이밍 UI | "지금 이사하면 비늘 +N" 실시간 표시, 직전 환생보다 N이 2배 이상이면 버튼이 반짝임 |

## 12. 기술 설계 (Godot 4.7)

### 12.1 폴더 구조

```
뽑기키우기/
├─ project.godot
├─ scenes/main.tscn            # 루트 씬 (UI는 코드로 구성)
├─ scripts/
│  ├─ autoload/
│  │  ├─ balance.gd            # Balance: 모든 수치 공식·상수
│  │  ├─ dragon_db.gd          # DragonDB: 드래곤·적·챕터 데이터
│  │  ├─ game_state.gd         # Game: 저장 데이터, 재화, 시그널, 세이브/로드, 오프라인
│  │  └─ gacha.gd              # Gacha: 확률 추첨, 천장, 기계 레벨
│  ├─ util/num.gd              # Num: 큰 수 표기 (K, M, B, T, aa…)
│  ├─ main.gd                  # 레이아웃, 탭 전환, 팝업
│  ├─ battle/battle_view.gd    # 전투 시뮬레이션 + 그리기
│  ├─ gacha/claw_machine.gd    # 인형뽑기 기계
│  └─ ui/
│     ├─ dragon_art.gd         # 절차적 드래곤 그리기 (속성·등급·별 반영)
│     ├─ dragon_panel.gd
│     ├─ growth_panel.gd
│     └─ mission_panel.gd
└─ (art/, audio/ 는 M1에서 추가)
```

### 12.2 원칙

- **수치는 전부 `balance.gd` 한 곳에** 둔다. 기획 수정이 코드 한 파일 수정으로 끝나게 한다. `tools/balance_sim.py`와 공식을 맞춘다.
- **데이터와 표현 분리**: `Game`이 상태를 들고 시그널(`currency_changed`, `dragon_changed`, `stage_changed`)을 쏘고, UI는 구독만 한다.
- **세이브**: `user://save.json`, 30초마다 자동 저장하고 앱이 백그라운드로 갈 때·종료할 때도 저장한다. `version` 필드로 마이그레이션한다.
- **프로토타입 아트**: 외부 에셋 없이 `_draw()`로 드래곤·적·기계를 그린다. M1에서 스프라이트로 교체할 때는 `dragon_art.gd`만 바꾸면 된다.
